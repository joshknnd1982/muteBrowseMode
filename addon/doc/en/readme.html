Mute Browse Mode

NVDA normally announces a browse mode document every time one is entered: the document name, the word "document", and the first line of the buffer. That happens when a web page finishes loading in Chrome, when you switch to a browser window, and when you open a message in any version of Microsoft Outlook.

This add-on adds two combo boxes to NVDA's Browse Mode settings (NVDA menu, Preferences, Settings, Browse Mode).

Mute browse mode

The first combo box has three choices.

Silence all browsing

NVDA stays silent while a document is loading and when it has finished loading. "Loading document..." is not spoken either. Reading the page yourself with the arrow keys, quick navigation keys and everything else works exactly as usual.

Play tones

Speech is silenced the same way, but three quick ascending tones are played when the document is ready, so you still know when you can start reading.

Normal

NVDA behaves exactly as if the add-on were not installed. This is the default.

Announce a page summary when a page has loaded

The second combo box decides what happens in a web browser once a page has finished loading, in place of the announcement the first combo box silenced. It also has three choices.

Speak the summary

NVDA says "Loading complete", then how much is on the page, for example:

Loading complete
Page has 8 regions, 57 headings and 196 links

This is the default. Regions are what NVDA elsewhere calls landmarks, and the counts are the same ones the Elements List would give you.

Play tones

Three quick ascending tones are played instead of the summary. If the first combo box is set to play tones as well, you still only hear them once.

Normal

No summary. NVDA does whatever the first combo box leaves it doing.

Say "loading complete" before the page summary

A check box under the two combo boxes. Untick it and the summary is just "Page has 8 regions, 57 headings and 196 links", with no "Loading complete" in front of it. It is ticked to start with.

Links are on their own line

A check box, not ticked to start with. Tick it and a message in Outlook puts every link, button and other control on a line of its own, so you can down arrow through them one at a time.

So a message reading "comment this is a link" is now two lines: "comment", and then the link on its own, one down arrow away.

Outlook shows messages in two completely different ways, and the check box covers both.

A message shown as a web page, which is what Outlook on the web and the new Outlook for Windows do, gets the same treatment NVDA's own "Use screen layout (when supported)" gives a web browser, applied to Outlook on its own so the setting your browsers use is not touched. If you already have NVDA's screen layout switched off, there is nothing to add and the check box stays out of the way.

A message that Word renders, which is what classic Outlook does, is not a web page at all, and NVDA has no screen layout to switch off there. Its lines are Word's own, so a link in the middle of a sentence is read out as part of that sentence. For those, the down and up arrow keys walk the line a piece at a time instead, stopping either side of every link and button. Nothing else about the message changes: braille still shows the whole line, say all still reads it as it always did, and anything at all unexpected falls straight back to the way NVDA moves normally.

The Outlook spelling checker

When the F7 spelling window takes the focus, NVDA says the word the checker is asking about, and then spells it out. The spelling is read a fifth more slowly than your usual rate, and your rate goes straight back to normal after it.

The slower rate is part of that one announcement rather than a change to your synthesiser, so it cannot be left behind anywhere else, not even if you interrupt the spelling half way through. Nothing outside the spelling window is affected at all.

The word is whichever one the checker has stopped on: Word selects the error in the message itself as it steps through, and the box in the dialog is pointed at that same selection. Moving on to the next error says that one; the same word is not said twice if the focus moves around inside the dialog. If the word cannot be worked out, nothing is said and NVDA carries on as usual, because the box holds the whole sentence the error is in and reading that out would be worse than saying nothing.

Switching windows

Nothing is ever silenced while NVDA is announcing a window you have just switched to. The title of the window, and the control the focus landed on, are always read right to the end first, and only then does the silencing start again. The one thing that stays silent throughout is the browse mode document itself, which is the whole point of the add-on.

"Read right to the end" is the synthesiser's word for it, not a guess at how long a title takes: the add-on asks NVDA to tell it when speech has actually reached the end of the announcement. This holds however fast you cycle through windows, including holding alt down and pressing tab several times: what NVDA was saying about a window you have already left can never end the announcement of the one you have arrived in. Pressing a key ends the wait early, because you have stopped listening and started working.

The title of a browser window is read out in full when you switch to it, even though browser window titles are silent the rest of the time. Switching between two browser windows needs this: the alt and tab switcher names each window as you cycle through them, and the moment one is actually activated NVDA stops that mid word, so with nothing said afterwards all you were left with was the fragment the switcher got through. Nothing that happens while the title is being read can cut it short either, including the browse mode document arriving behind it. Microsoft Outlook is the exception, because there the brief description of the focus takes the title's place.

Switching to Microsoft Outlook

When you switch to Outlook from another program, NVDA answers with a brief description of where you have landed: the field the focus is in, what the focus is, what is in it, and where it sits, for example:

Inbox, list, Josh Kennedy build 1.4, list item, 3 of 57

Where the focus is a control that holds a choice rather than a list of them, such as a combo box, the selected item is included too.

This replaces NVDA's own report rather than being added to it, so nothing is said twice. NVDA still does everything else it would have done, so braille and NVDA's own caches are exactly as they always were. It only happens when Outlook was not already the program you were in, and only when the first combo box is not set to Normal.

The Outlook message body

Tabbing through a new message goes To, Cc, Subject, and then the body. NVDA names the first three, but the body has no name for it to read, so there is nothing to tell you that you have reached the part you are meant to type into. When the focus lands there, NVDA now says:

You are now in the message body, type a message.

It is said after NVDA's own announcement of the field, and only for the message body itself. Nearly everything on a message form is an editable field, so "can this be typed into" is not the test. The body is identified instead: NVDA marks the message body object as such, the editor Outlook composes in has a window of its own that no field and no dialog shares, and the plain text body is the one rich edit control NVDA picks out by name and number. The box in the F7 spelling dialog is left alone as well, even though Word marks it up the same way, because it is not that editing window. A body that cannot be typed into, such as the one in the reading pane, is left alone too, because the announcement invites you to type.

Tabbing away and back says it again; a message body raising a second focus event on its own does not. Like the rest of the Outlook behaviour, it is quiet when the first combo box is set to Normal.

Where the summary happens, and where it does not

The summary is only ever announced when Microsoft Outlook is not the program you are in. That is checked, silently, every single time: the add-on looks at the program in the foreground and at where the focus is, and nothing about that check is ever spoken. Outlook is the one place the add-on is meant to be quiet, and opening a message there stays as quiet as it was before.

It is announced in web browsers and Electron applications: Chrome, Edge, Brave, Opera, Vivaldi and other Chromium based browsers, Firefox and other Gecko based browsers, and anything built on Electron. The new Outlook for Windows is built on the same engine as Chrome, so it is recognised as Outlook first and stays silent.

Other things that stop the summary:

  • a page loading in a background tab, which is only announced if you go to it;
  • pressing a key while the page finishes loading, which means you have stopped waiting for it and started using it;
  • "Automatically say all on page load" being on, so the summary never talks over the page being read to you.

Control+F

In a web browser, control+F opens NVDA's find. NVDA's find searches the page from where your cursor is and leaves the cursor on what it found, so the next line down is the line after the match, and NVDA+F3 carries on from there. A browser's find bar only scrolls the page and puts the keyboard somewhere else entirely.

It is also the one that keeps working. An embedded document that has taken the focus swallows the browser's control+F, so the find bar silently refuses to open; NVDA's find has no such problem, because it never leaves the buffer.

Everywhere else control+F reaches the program untouched. In Microsoft Outlook it forwards the message you are reading, which is what control+F does in Outlook. In Word it is Word's find. In focus mode it belongs to whatever you are typing in, and where NVDA has nothing to search — the address bar, or the browser's own find bar — it goes straight back to the browser.

Two check boxes in Browse Mode settings control this:

  • "Control+F opens NVDA's find in a web browser", ticked by default — browsers only.
  • "Bring up NVDA screen reader find when not in Outlook", unticked by default — everywhere except Microsoft Outlook. Where both are ticked this one wins, being the wider of the two. Untick both and control+F always reaches the program.

"Everywhere" means everywhere NVDA has a browse mode document to search, which outside a browser is Kindle, PowerPoint, an OCR result and UIA web content. A Word document is not one of those, so control+F in Microsoft Word remains Word's own find whatever these check boxes say.

NVDA's find is on NVDA+control+F either way, with NVDA+F3 and NVDA+shift+F3 for the next and previous match.

The binding is added and taken away as you move between programs, rather than being left in place and the key handed back. A key NVDA has a script for is trapped, so the real keystroke never reaches the program and what it gets instead is a synthetic one injected a moment later — which is not the same thing, and is not what should be arriving in Outlook when you forward a message. Between 1.3 and 1.9 the add-on did exactly that, for no benefit at all, and it is why the binding was removed in 2.0 before coming back in 2.3 with a job to do.

Outlook and Chromium browsers

In Microsoft Outlook and in every Chromium based browser, the two silencing choices go further than they do elsewhere. As well as the document announcement, NVDA no longer speaks:

  • window titles, so switching to Outlook no longer reads the title of the message list window, and opening a message no longer reads the title of the message window;
  • dialogs, so opening an Outlook message no longer says the word "dialog";
  • document titles, so a browser tab no longer announces the page title;
  • toasts and notification balloons, such as a browser's download and pop-up messages;
  • live region "flash" messages, which is how web pages announce things like "Message sent" or "Your changes were saved".

Every Chromium based browser is covered, including Chrome, Edge, Brave, Opera, Vivaldi and forks of them, because the add-on recognises them by the windows Chromium creates rather than by a list of program names. The new Outlook for Windows is recognised the same way, as it is built on the same engine.

You can still ask for any of this at any time. NVDA+t reads the title, NVDA+tab reads the focus, and NVDA+b reads a whole dialog, exactly as usual: only the announcements NVDA makes on its own initiative are dropped.

Notes

  • Pressing any key immediately restores normal speech, so the add-on can never leave NVDA quiet when you are trying to work.
  • Braille is untouched. The document, the current line, alerts and flash messages are all still brailled, including the ones that are no longer spoken.
  • Moving around inside a document with tab, the arrow keys and the quick navigation keys always speaks. Only arriving in a document from outside it is silenced.
  • Say all is never silenced. If you use Browse Mode settings, "Automatically say all on page load", NVDA will still read the page to you after it loads. Turn that setting off if you want the silence.
  • If Browse Mode settings, "Audio indication of focus and browse modes" is on, you will still hear that short sound when a document is entered, because it is a sound rather than speech. Turn it off and NVDA speaks "browse mode" instead, which this add-on does silence.
  • Commands to cycle each combo box are in the Input Gestures dialog under "Mute Browse Mode". Neither has a gesture assigned unless you assign one, and the add-on claims no keyboard shortcut of its own.
  • A page with an enormous number of links is not counted all the way to the end, so that NVDA is never held up by it. The summary says "over 1500 links" when that happens.

Changes

2.4

  • New check box in Browse Mode settings: "Bring up NVDA screen reader find when not in Outlook", unticked by default. Tick it and control+F opens NVDA's find everywhere except Microsoft Outlook, rather than only in a web browser. Where both find check boxes are ticked this one wins, being the wider of the two.
  • Outlook is still the exception, because control+F is Forward there.
  • It reaches everywhere NVDA has a browse mode document to search, which outside a browser means Kindle, PowerPoint, an OCR result and UIA web content. A Word document is not one of those, so control+F in Microsoft Word is still Word's own find whatever these check boxes say.
  • Control+F is now claimed only where there really is a document for NVDA to search, rather than wherever the program qualifies. So the address bar, the browser's own find bar and every program without a browse mode document keep receiving control+F as the key you actually pressed, with nothing injected in its place.

2.3

  • Control+F in a web browser now opens NVDA's find instead of the browser's own find bar. NVDA's find searches the page from where your cursor is and leaves the cursor on what it found, so the next line down is the line after the match, and NVDA+F3 carries on from there. It also keeps working where the browser's does not: an embedded document that has taken the focus swallows the browser's control+F, but NVDA's find never leaves the buffer.
  • Only in a web browser, and only in browse mode. In Microsoft Outlook control+F is still Forward, in Word it is still Find, and in focus mode it still belongs to whatever you are typing in. Where NVDA has nothing to search — the address bar, or the browser's find bar itself — control+F is handed straight back to the browser.
  • A new check box in Browse Mode settings, "Control+F opens NVDA's find in a web browser", ticked by default, turns it off again.
  • NVDA's find is still on NVDA+control+F as well, with NVDA+F3 and NVDA+shift+F3 for the next and previous match.

2.2

  • Fixed the real cause of control+F and enter appearing to do nothing in Microsoft Edge. Some pages have an embedded document — an iframe, such as the "Image Magnify" frame on a product page — that takes the focus when you move the browse cursor near it, for instance with control+home or by arrowing up to the top. While the focus is inside one of those, the browser's own control+F never opens the find bar, and the enter you press afterwards is taken by browse mode as "activate what is under the cursor", so nothing happens. NVDA normally warns you by announcing the embedded document, but the add-on was dropping every document announcement in a browser, so there was nothing at all to say the keyboard had left the page.
  • Document announcements are now dropped only at the moments the add-on exists for: while a page is loading, while a document is being entered, and while a window you have just switched to is being announced. A document that names itself outside all three has taken the focus on its own, and is now always spoken.
  • Added an optional trace, off unless a file named muteBrowseModeTrace.on exists in your temp folder, which records every keystroke and focus change to muteBrowseModeTrace.log beside it. It is what found this, and it works with NVDA's own logging turned off.

2.0

  • Fixed enter doing nothing in Microsoft Edge's own find bar. Pressing control+F opened the find bar and you could type into it, but pressing enter did not run the search. The add-on had bound control+F to a script of its own since 1.3, which meant NVDA trapped the key and injected a synthetic one in its place instead of letting your keystroke through. The binding is gone. Nothing in NVDA binds plain control+F in the first place, so it already reached every program on its own, and it still forwards the message in Outlook and opens the find bar in a browser.
  • The add-on no longer claims any keyboard shortcut. The two cycle commands are still in the Input Gestures dialog with no gesture assigned.

The slower rate belongs to that one announcement rather than to your synthesiser, so nothing outside the spelling window is affected.

1.6

  • Fixed "You are now in the message body" being said for every field on an Outlook message form. Nearly all of them are editable, and the ones the user tabs through on the way to the body, To, Cc and Subject, are rich edit controls that take more than one line, which is exactly what the body was being recognised by. The body is now identified rather than guessed at, from the marker NVDA's own Outlook support puts on it, from the window Outlook composes in, and from the control number of the plain text body.
  • Fixed only part of a browser window's title being read when switching between two browser windows. The window title is now read out in full on a switch, and nothing that happens behind it can cut it short.

1.5

  • Fixed the title of a window being only half read when you switch to it straight after leaving Microsoft Outlook. NVDA hands back "this has now been spoken" through its event queue, so one belonging to the window you have just left arrives after the switch to the next one has already begun. It was being counted against the new window's announcement and ending it early, which cut the title off. Each announcement is now numbered, and a message from a window you have left is ignored.
  • An announcement also now stays open for a moment after the last thing NVDA said, rather than closing on the spot, so a gap between two parts of it cannot end it either.
  • Tabbing into the body of a message in Outlook now says "You are now in the message body, type a message."

1.4

The silence now stands down for the whole of that announcement and starts again only once the synthesiser has finished saying it.
  • Switching to Microsoft Outlook from another program now answers with a brief description of the field the focus is in, what is in it, and the selected item where there is one, in place of NVDA's own report.
  • Added a check box for the "loading complete" part of the page summary.

  • Both combo boxes have moved from Speech settings to Browse Mode settings, which is where the rest of NVDA's browse mode settings live.
  • Control+F is now handed straight to the program instead of ever being claimed by NVDA, so it forwards the current message in Microsoft Outlook. NVDA's find is on NVDA+control+F.
